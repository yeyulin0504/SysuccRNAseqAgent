# bulk RNA-seq Agent 精简科研工作台界面设计

- 日期：2026-09-07
- 状态：用户已确认核心方向的设计基线
- 参考：借鉴 DeepScience 的项目工作区、持续会话、运行过程和产物面板，但不复制其通用多 Agent、终端、Connector 和完整科研平台功能
- 当前范围：只服务 bulk RNA-seq Agent

## 1. 设计目标

界面要让不熟悉命令行的科研用户始终知道四件事：自己在哪个项目、正在讨论什么、分析进行到哪一步、当前决定会影响哪些结果。

首版采用三页结构：

1. **项目首页**：新建、打开、归档项目，显示最近状态和需要处理的检查点。
2. **分析工作台**：集中完成对话、样本、流程、结果和人工决策。
3. **设置页**：管理 HPC 连接、参考资源和 AI 模型，不把这些技术配置散落在分析页面。

## 2. 工作台布局

```text
┌─────────────────────────────────────────────────────────────────┐
│ 项目名 │ Bulk RNA-seq │ HPC 状态 │ 当前作业 │ 告警 │ 设置       │
├──────────────┬─────────────────────────────┬────────────────────┤
│ 项目/对话     │ 当前对话                    │ 项目上下文           │
│              │                             │                    │
│ ＋新建对话    │ Agent 消息与用户消息         │ 流程进度             │
│ 主分析流程    │                             │ 样本与数据           │
│ QC 讨论       │ 计划、工具动作、检查点卡片    │ 运行与结果           │
│ DE 结果解释   │                             │ 报告与产物           │
│              │ 输入框与结构化快捷操作        │                    │
└──────────────┴─────────────────────────────┴────────────────────┘
```

桌面端采用三栏。窄屏时右栏变为抽屉，左栏保持可折叠；首版不为手机端承担大矩阵和复杂图形分析。

### 左栏：项目与对话

- 顶部显示当前项目并提供返回项目首页。
- 对话列表按最近活动排序，显示标题、状态和最后更新时间。
- 支持新建、重命名、归档和继续对话。
- 新建对话为干净聊天上下文，可以读取项目有效结果，但不自动载入其他对话内容。
- 首版不做对话合并、跨项目移动、多人共享和自动长期记忆。

### 中栏：对话与决策

- 普通消息保持简洁；分析计划、工具调用和检查点使用可展开卡片。
- 卡片显示能力名称、输入、参数、目标阶段、预计资源、状态和实际结果来源。
- 关键操作使用结构化按钮，例如“确认并运行”“修改参数”“排除样本”“终止”。自由文本不能绕过后端规则。
- 对话只提出项目级操作。实际运行显示稳定的 run ID，用户从任何对话进入都看到同一个真实状态。

### 右栏：项目上下文

使用四个页签：

- **流程**：输入检查 → FASTQ QC → 比对定量 → 融合 → 差异表达/富集 → 报告。
- **样本**：样本表、配对、分组、批次、文件验证和排除状态。
- **运行**：排队、运行、等待确认、失败、完成及恢复操作。
- **结果**：QC、counts、TPM、融合、DE、富集、报告和下载；不适用模块明确显示原因。

右栏呈现项目事实，不受当前对话措辞影响。每个结果链接到其 spec revision、run attempt 和 artifact 来源。

## 3. 多对话与项目状态模型

```text
Project
├── Thread A ── Message...
├── Thread B ── Message...
├── Spec Revision 1
│   └── Run Attempt 1 ── Artifact...
└── Spec Revision 2
    └── Run Attempt 2 ── Artifact...
```

关系规则：

1. `thread_id` 属于一个且仅一个 `project_id`。
2. Message 保存用户文字、Agent 回复和对项目操作的引用，不保存科学结果副本。
3. Spec、run 和 artifact 属于项目；对话只通过 ID 引用它们。
4. 新对话默认可检索当前项目的 `VALID + CONSUMABLE` 产物和活动任务摘要。
5. 新对话不能自动读取其他对话消息。用户明确选择“引用另一对话”后，只附加所选消息的只读引用及来源。
6. 对话归档不改变分析状态；删除对话也不得级联删除项目数据。首版建议只开放归档，删除放入后续版本。
7. 两个对话请求相同执行时，后端返回已有 run；若参数不同，必须形成新的计划或规格修订。

## 4. 导航与典型流程

用户在项目首页新建项目，填写项目名和研究目标后进入工作台。系统自动创建“主分析流程”对话，但用户可以立即新建其他对话。

主分析流程建议按以下体验推进：

```text
上传/登记 FASTQ
→ 样本检查与分析计划
→ 用户确认计划
→ FASTQ QC 作业
→ 项目进入“需要确认”
→ 用户可从任一对话打开同一 QC 检查点
→ 继续比对、定量和融合
→ 合格队列进入 DE/富集
→ 项目级报告
```

例如用户可以在“QC 讨论”询问某个指标，在“主分析流程”点击继续。后端必须把两者绑定到同一 QC artifact 和检查点，不能分别创建两个流程副本。

## 5. 可见状态与反馈

项目列表和工作台统一使用：草稿、等待确认、排队、运行中、部分完成、失败、已完成。科学门禁另显示 `WARN`、`NOT_EVALUABLE` 或 `FAIL_OUTPUT_CONTRACT`，不能混为服务器失败。

检查点卡片至少显示：暂停原因、证据、可选操作、选择影响的下游阶段，以及作出决定的用户/时间/对话。关闭网页不会取消任务；重新打开后恢复同一状态。

## 6. 首版验收

- 一个项目可创建至少三个独立对话，刷新后标题、顺序和消息仍存在。
- 新对话能看到项目有效产物和活动作业摘要，不能看到其他对话的消息正文。
- 同一项目两个对话触发相同冻结请求时只存在一个 HPC run。
- 从任意对话确认 QC 时，决定绑定同一 artifact、修订和检查点，所有页面同步更新。
- 归档对话后，样本、运行和结果不丢失。
- 切换项目后，不显示前一项目的对话、文件、任务或结果。
- 无 LLM 模式仍能通过结构化页面创建项目、完成检查点和查看报告。

## 7. 暂缓功能

首版不实现通用文件编辑器、终端、代码运行器、科学数据库 Connector、对话 Fork/合并、跨项目引用、多人实时协作、WES/scRNA 页签和模型市场。未来增加组学模块时沿用项目、对话、运行、产物分层，不重建会话系统。
