# RNA-seq SSH 工作流可用性修复设计

日期：2026-09-28

## 目标

修复已经配置 SSH 服务器时，RNA-seq 主流程中从远程 FASTQ 扫描到网页结果展示的断点。范围包括服务器 FASTQ 扫描、样本分组、计划确认、远程执行、状态等待、结果校验和报告展示；不新增 WES、单细胞或新的统计方法。

## 用户流程

```text
SSH 连接检查
→ 扫描服务器目录
→ 识别 R1/R2 配对
→ 生成样本候选
→ 用户补充分组和实验信息
→ 生成可审阅计划
→ 用户确认并冻结契约
→ 提交远程任务
→ 区分排队/运行/成功/失败
→ 校验并登记结果产物
→ 在 History 和报告中展示
```

扫描结果、用户分组、计划、契约、任务和产物必须写入同一个项目状态，网页、对话和 CLI 读取同一份状态，不能各自维护一套临时状态。

## 输入与扫描

- 使用已经保存并通过连接测试的 SSH 配置。
- 扫描只读目录，识别常见 `.fastq`、`.fq` 及 gzip 文件。
- 支持 `_R1/_R2` 和兼容的单下划线读段命名。
- 每个样本必须有唯一 R1/R2 配对；不完整、重复或无法识别的文件进入明确的 unmatched 列表。
- 扫描结果保存 canonical directory、样本候选、未匹配文件、扫描时间和来源引用；网页只展示必要摘要。
- SSH 未配置、认证失败、目录不存在和扫描命令失败必须返回可理解的错误，不得显示空成功结果。

## 样本与计划

- 扫描出的样本候选可以写入项目草稿，但不能自动猜测 condition、癌种或配对关系。
- 用户可批量编辑样本分组；保存后重新运行输入门禁和计划生成。
- 计划必须展示样本数、分组、参考基因组、启用的步骤和预计产物。
- 用户确认后生成不可变 Analysis Contract；后续执行只能使用该契约。
- 修改样本、参考或流程参数必须生成新版本并使旧计划失效。

## 执行与状态

- 提交前确认 SSH、远程工作目录、调度器和工具/容器配置完整。
- 任务状态必须区分 queued、running、completed、failed、result_missing 和 unavailable。
- 使用等待和轮询接口时，只有远程任务明确终止且产物校验完成后才进入 completed。
- 排队或运行中不能提前进行结果校验，也不能显示结果缺失。
- 旧任务不能覆盖新契约产生的结果；结果必须绑定 project、contract、attempt 和 stage。

## 结果与报告

- 结果校验必须确认必需产物存在、文件格式正确、哈希和 manifest 一致。
- History 展示输入、样本确认、契约、运行、产物和报告，并能看到失败原因。
- 报告只能引用当前项目和当前契约有效的产物；缺失或失效产物要明确标记。
- counts/表达矩阵路线沿用现有 raw counts 门禁，不把 normalized/GEO matrix 伪装成 DESeq2 输入。

## 验收测试

1. 已配置 SSH 时，扫描可识别 R1/R2 并生成样本候选。
2. 不完整配对、重复样本和扫描失败均返回结构化错误。
3. 样本分组保存后进入计划，计划内容与配置一致。
4. 确认后契约冻结，执行使用同一 contract ID。
5. queued/running 不触发结果缺失；completed 只在产物校验通过后出现。
6. 失败、unavailable 和 result_missing 在网页、对话和 CLI 中使用同一语义。
7. History 和报告能展示当前输入、任务和产物。
8. counts 路线的 raw/normalized 判断和 DESeq2 门禁保持正确。
9. 现有权限、审计和旧测试不回归。
