# SYSU RNA-seq Agent 产品设计规格（v1）

## 1. 产品定位

SYSU RNA-seq Agent 是面向实验室科研人员的**受控型 RNA-seq 工作流应用**。它以固定、可审计的分析流程为执行核心，并在其上提供自然语言辅助、配置引导、运行诊断和结果解读。

它不是允许模型自由调用 shell 的通用代理，也不替代研究者对实验设计、统计方法和生物学结论的判断。

**核心原则：**

1. 确定性流程负责分析执行；LLM 只负责受限的理解、建议与解释。
2. 外部副作用必须可见、可审计，并经用户明确确认。
3. 原始数据和潜在敏感数据默认不发送到模型服务。
4. 每次运行必须保留可复现的配置、脚本、日志、输入和结果清单。

## 2. 目标用户与典型任务

| 用户 | 主要需求 | 系统支持 |
| --- | --- | --- |
| 湿实验研究生 | 不熟悉命令行，需完成标准 RNA-seq 流程 | 向导、对话补全配置、错误解释、状态提示 |
| 生信分析人员 | 需要查看、复用和审计具体运行 | JSON 配置、固定 Profile、合同、脚本、运行清单 |
| 导师/平台主管 | 需要检查流程边界和结果可信度 | 只读预检、报告、状态、版本与指纹记录 |

第一版优先支持 bulk RNA-seq：FASTQ 质控、比对、表达定量和可选融合基因检测；不自动给出疾病诊断或临床决策。

## 3. 系统边界

### 3.1 固定执行内核

执行内核仅调用仓库已支持、经配置声明的工具和步骤：`fastp`、`STAR`、`featureCounts`、`RSEM` 与可选 `Arriba`。支持 Slurm、PBS 和受控的远程后台执行。

`free` 模式仅表示项目配置可修改，不表示 LLM 可以生成或执行任意命令。`skill` 模式使用版本化固定 Profile；`contract` 模式在提交前验证配置、输入 FASTQ 和渲染脚本指纹。

### 3.2 受限分析代理

受限分析代理是 GUI 与 chat 中的上层助手。它接收用户自然语言并选择预定义动作，不具有远程 shell、文件系统写入、上传或调度器提交权限。

它可以：

- 解释 RNA-seq 概念、固定流程和工具输出；
- 识别用户意图，如新建项目、补全信息、校验、查看状态或阅读报告；
- 从用户已提供的信息生成**待审阅**的配置建议；
- 解释本地校验、预检、上传、调度与结果下载中的结构化错误；
- 解读已脱敏的 QC/运行摘要，并标注需要人工复核的结论；
- 提示下一步操作及其风险、前置条件和预期产物。

它不可以：

- 生成、修改或直接执行任意 shell、SSH、Slurm、PBS 或容器命令；
- 绕过 Profile、合同、校验或用户确认；
- 自动上传 FASTQ、创建远端目录、提交/取消任务、下载结果或发送邮件；
- 读取或向模型服务发送 FASTQ、BAM、完整表达矩阵、患者标识、SSH/SMTP/API 凭据；
- 将统计关联自动表述为生物学或临床结论。

## 4. 分层架构与职责

| 层级 | 组件 | 职责 | 不承担的职责 |
| --- | --- | --- | --- |
| 交互层 | GUI、CLI、chat、wizard | 收集信息、展示预览、确认操作、展示状态 | 隐藏关键参数或静默执行 |
| 代理层 | 规则路由与可选 LLM 路由 | 意图识别、问答、配置建议、诊断解释 | 任意命令生成与执行 |
| 策略层 | action allowlist、数据分级、确认门 | 验证允许动作、脱敏、确认和审计 | 替代领域专家审批 |
| 工作流层 | config/profile/contract/validation | 配置、固定流程、输入校验、合同验证 | 解释自然语言 |
| 执行层 | SSH/SCP、脚本生成、scheduler | 上传、提交、轮询、下载、解压 | 接受模型直接控制 |
| 证据层 | attempt、manifest、logs、report | 保存输入指纹、脚本、状态、结果与报告 | 保存密钥或原始敏感内容 |

所有 LLM 建议先转换为结构化的 `proposed_action` 或 `config_patch`，再经本地 schema、策略和 UI 审阅；模型文本本身不得成为执行指令。

## 5. 操作分级与确认机制

| 级别 | 示例 | 是否需要确认 | 可由 LLM 触发 |
| --- | --- | --- | --- |
| A：只读解释 | 概念问答、报告说明、错误解释 | 否 | 是 |
| B：本地无副作用检查 | 校验配置、估算时间、查看缓存状态 | 用户可直接点击 | 仅可建议/请求，不能静默执行 |
| C：本地持久化变更 | 新建项目、保存配置、应用 Profile、冻结合同 | 展示差异后确认 | 仅生成待审阅建议 |
| D：远端或外部副作用 | 预检、上传、创建远端目录、提交/取消作业、下载、邮件 | 每次显式确认 | 否；只能引导用户点击 |

确认界面至少展示：动作名称、目标项目/服务器别名、会修改或传输的对象、关键资源参数、预期输出、可逆性和失败影响。执行前再次由本地策略校验配置、权限和合同状态。

## 6. 数据、隐私与凭据策略

### 6.1 默认数据最小化

默认发送给模型服务的内容仅限用户输入的文本、工具名/版本、经用户确认的少量配置字段、脱敏错误摘要和聚合 QC 指标。模型请求应显示“将发送的摘要”预览，并允许用户取消。

禁止外发的内容包括原始 FASTQ/BAM/CRAM、完整计数矩阵、样本名或患者标识、服务器地址与用户名、远程绝对路径、访问令牌、SSH 私钥、密码和 SMTP/API Key。

### 6.2 凭据处理

API Key、临时 SSH 密码和 SMTP 密码仅驻留在当前进程内存或用户选择的本机安全凭据存储中；不得写入 `project.json`、defaults、运行清单、日志、报告或远程服务器。日志输出必须执行凭据掩码。

### 6.3 结果解释边界

代理只能基于已生成的受控摘要解释数值含义和限制。任何差异表达、融合或通路层面的解释必须注明所用输入、阈值、统计方法与人工复核要求，且不得用于临床诊断。

## 7. 核心用户流程

1. 用户在 GUI/wizard/chat 说明研究目标。
2. 代理询问缺失的结构化信息：样本、分组、单双端、链特异性、参考版本和服务器设置。
3. 系统生成待审阅的 `project.json`；用户检查并保存。
4. 用户运行本地 FASTQ 与配置校验；错误以可操作语言展示。
5. 用户可应用固定 Profile，并在需要严格重放时创建合同。
6. 代理解释预检结果、资源估计和建议；用户决定是否继续。
7. 用户在确认页明确启动上传和任务提交；执行层创建独立 attempt 并记录运行清单。
8. 用户主动刷新状态或启用本地轮询；系统展示作业状态和脱敏日志摘要。
9. 完成后用户确认下载；系统安全解压、验证结果清单和关键产物，并生成报告。
10. 代理依据报告和聚合指标提供结果阅读提示与人工复核清单。

## 8. 可复现性与审计要求

每次 attempt 独立保存在 `runs/<project_id>/attempts/<run_id>/`，至少包含：项目快照、渲染脚本、运行清单、代理/执行日志、下载产物和结果 manifest。

合同模式必须在建立 SSH 连接前验证工作流配置、FASTQ、渲染脚本及合同正文的 SHA-256；存在漂移即拒绝执行。审计记录应区分“模型建议”“用户确认”“本地校验结果”“执行请求”“远端状态”和“结果验证”，并不得包含敏感明文。

当前可声明的是本地输入—配置—脚本合同验证；远端工具版本、参考/index checksum、上传后 checksum、完整资源账单和追加式 hash-chain 仍是后续增强项，不能表述为生产级合规认证。

## 9. 失败处理与人工接管

- 配置或 FASTQ 校验失败：阻止后续执行，说明字段/文件问题并给出修正路径。
- 合同验证失败：在任何 SSH 连接前停止，列出发生漂移的对象。
- 远端执行失败：保留 attempt、状态和脱敏日志；代理只能解释和建议，用户决定重试或修改配置。
- 模型不可用或输出不合规：退回本地规则路由与普通 GUI/CLI，不影响确定性执行功能。
- 模型建议无法通过 schema 或策略验证：丢弃该建议并显示安全提示，不尝试猜测或转换成命令。

## 10. 验收标准

### 10.1 功能验收

- 用户可在无 LLM 情况下完成配置、校验、执行、状态查询、下载和报告。
- LLM 只能返回 allowlist 中定义的结构化建议；不产生可执行 shell 文本。
- 所有 C/D 级动作均在 GUI 显示参数与影响后，等待用户明确确认。
- 配置、FASTQ、Profile 与合同漂移能在规定阶段被阻止并解释。
- 每次运行生成独立 attempt 与完整的非敏感审计材料。

### 10.2 安全与隐私验收

- 自动测试证明模型输入不含 FASTQ/BAM、凭据、服务器地址、用户名、远程路径和患者标识。
- 自动测试证明模型无法直接调用上传、提交、下载、邮件和取消任务接口。
- 日志、报告、异常栈和 UI 预览均不泄露凭据。
- 用户拒绝确认后不得产生远端副作用。

### 10.3 科研可用性验收

- 固定 Profile 能端到端完成已定义 RNA-seq 步骤，并输出预期产物。
- contract 模式可检测本地输入、配置和脚本漂移。
- 报告可明确展示流程、版本、状态、结果路径、QC 摘要与限制。
- 至少提供一个可公开、可复现的最小 demo 或完整运行记录。

## 11. 迭代范围

**v1：** 受限对话助手、allowlist、确认门、数据最小化、配置建议、错误解释、报告阅读提示与端到端 demo。

**v1.1：** 远端 FASTQ/参考/索引 checksum、工具环境锁定或 Apptainer digest、调度器资源账单、语义一致性指标和追加式审计链。

**后续：** 在通用项目/执行框架稳定后，以独立 adapter 增加 ChIP-seq；WES 因 tumor-normal 配对、变异注释和临床隐私风险，最后单独设计并加强人工审核。

## 12. 现状差距与实施顺序

现有实现已经具备 action allowlist、非 JSON/未知动作回退、Codex CLI 的只读隔离调用，以及 `run` 前的确认对话。但它尚未完全满足本规格中的严格受限边界：模型路由的 `run` / `run-nowait` 当前可在确认对话后调用执行函数；GUI 的本地快捷指令也可直接启动运行。第一版应将它们改为“生成执行预览并引导用户使用专用按钮”，使模型决策与执行入口彻底分离。

建议按以下顺序实施：

1. 将 LLM action schema 缩减为纯只读建议、解释和 `propose_config_patch`；删除模型可分派的 `run`、`run-nowait`、状态刷新等外部动作。
2. 新增本地策略模块：定义数据分级、可外发字段白名单、凭据/路径/样本标识掩码，以及结构化建议的 schema 校验。
3. 在 GUI 中增加“代理建议预览”区域：展示配置差异、将发送给模型的摘要、动作影响和拒绝按钮；持久化变更由用户在独立确认页提交。
4. 将远端操作统一收敛到显式 GUI/CLI 执行入口，并为预检、上传、提交、下载和取消操作分别展示影响与确认记录。
5. 为策略层补充单元测试和集成测试：敏感信息不得进入模型请求；模型输出不能触发执行；拒绝确认后没有远端副作用；LLM 故障时规则路由仍可用。
6. 使用公开最小数据或完整运行记录完成端到端 demo，并在报告中验证 attempt、manifest、合同和人工复核提示完整可追溯。
