# 交给 AI 的 bulk RNA-seq Agent 开发指导说明书

版本：v1.0 草案；日期：2026-09-04。

用途：将本文与当前仓库一起交给 AI 编程助手，让其在已有项目上分阶段完成 bulk RNA-seq Agent。本文是任务书与验收规范，不代表这些能力已经实现或通过真实 HPC 验证。本文不直接启动开发、上传数据或提交计算作业。

依据：`docs/superpowers/specs/2026-08-20-local-first-multiomics-agent-design.md`，重点对应第 5—8、10—16 节。原文的多组学路线保留，本次只实施其中 bulk 主线；模型插件、WES 和单细胞不作为本次验收条件。以下新增的工程选择均为本版草案要求。

## 1. 可直接复制给 AI 的启动指令

你是本项目的研发工程师，需要基于当前 SysuccRNAseqAgent 仓库，把 bulk RNA-seq 部分做成实际可运行、可恢复、可交互、可审计的研究分析 Agent。

请先完整阅读本说明书和它引用的多组学设计规范，检查项目中的 AGENTS.md、现有源码、测试和依赖，再开始工作。不要因为 README 写了“支持”或已有同名模块，就把能力判定为完成。

本次只做 bulk RNA-seq：人类 GRCh38、Illumina paired-end FASTQ，支持单样本表达与融合，以及符合条件的独立非配对两组 DESeq2 差异表达和 fgsea 富集。复用现有 Python、SSH/SFTP、调度器、工作流、合同及报告底座，完成 localhost 网页工作台和真正贯通的 LangGraph 主线。

先提交一份“现状—缺口—修改位置—验收证据”的对照表，再拆成可验收的小任务逐项实现。普通编码、局部修复和本地测试可以连续推进；仅对影响科学结果的未定规则、缺失的站点信息、真实数据传输和实际计算提交提出具体问题。不要在每一个文件修改后重复询问是否继续。已有授权在明确范围内持续有效。

每阶段都交付可运行结果、测试证据和剩余缺口。禁止用模拟输出冒充真实生信结果，禁止用测试通过冒充真实 HPC 跑通，禁止因为预算或时间不足把未完成项改写为完成。缺少服务器或参考资源时，完成本地实现、模拟故障测试和站点运行手册，并明确标记真实验收尚未完成。

详细范围、约束和验收以本文后续章节为准。

## 2. 最终要交付什么

交付一个安装在研究者电脑上的中文浏览器工作台。用户能够创建项目、在项目内新建多个对话、登记 FASTQ 和样本关系、查看分析计划、确认后运行、在真实 QC 结果出现时作决定、查看服务器任务、修改分析并恢复、阅读和导出有证据来源的报告。

产品应支持三种交互模式：本地或院内模型、经过明确外发授权的公共模型、无 LLM 的结构化表单。无 LLM 模式同样能完成全部确定性分析；自然语言用于理解问题、解释参数、提出受控操作和说明结果。

首个验收版本只包含 bulk 页面和能力，不显示可点击但尚未实现的 WES、单细胞、模型市场入口。

### 本次必做与排除项

| 必做 | 不在本次范围 |
|---|---|
| 本地 FASTQ 登记及 SFTP 上传、授权远程 FASTQ 登记 | 任意公共数据库自动搜索和下载 |
| fastp/MultiQC、STAR、featureCounts、RSEM、Arriba | 更换成另一套 RNA 工作流、任意工具菜单 |
| 单样本 QC、counts、TPM、融合候选 | 单样本差异表达或疗效结论 |
| 独立非配对两组 DESeq2、固定 fgsea 路线 | 配对、多因素、纵向、剪接、自定义统计公式 |
| 真实检查点、持久化恢复、版本化产物 | 多租户云平台、Electron 桌面壳 |
| bulk 研究报告、方法和审计导出 | WES、scRNA、跨组学、分型/疗效模型、自定义训练 |

保留未来扩展所需的清晰接口即可，不提前建设完整 Model Hub。既有 CMSclassifier 文档不构成本次接入指令。

优先核查这些具体缺口：

1. `node_wait_qc` 当前出现在 `execute` 前面。确认页面必须展示本次 fastp 已完成且校验过的 QC，不能在尚无结果时要求“确认 fastp QC”。
2. `execute` 当前直接连向 `validate_output`，而执行调用使用 `wait=False`。必须真正等待目标作业终止并完成结果获取，不能把排队或运行中的任务判为输出缺失。
3. `build_bulk_rna_graph()` 当前直接 `compile()`；核查是否配置了跨进程持久化 checkpointer，以及网页是否真正驱动这张图。
4. 输出校验和 post-run gate 节点当前可见空字典参数。必须接入本次 attempt 的真实 manifest 和 QC，不能让默认值制造通过。
5. 差异表达存在默认选取参考组的逻辑。正式计划必须让用户明确确认比较方向并冻结，不能静默按字母排序决定科研问题。
6. 搜索到了 DESeq2 渲染代码，但未在已检查的管线文件中确认完整 fgsea/MultiQC 执行链。逐项核实命令、版本、输入、输出和测试，不能把模块注释当实现。

先记录基线测试结果与已有失败。新增失败与历史失败分开说明；不重写无关模块、不覆盖用户修改。

## 4. 架构与执行边界

保留本地模块化单体：Python 3.11+、FastAPI、LangGraph、SQLite 持久化、已有 SSH/SFTP 和调度器适配器。前端优先扩展现有本地模板和资源；避免为本次任务引入另一套大型前端工程。依赖具体版本在基线冻结时锁定，不能把开放版本范围视为可复现环境。

固定调用链：

```text
网页/结构化对话
→ 能力解析与 Gate-A
→ Adapter.inspect/plan（只读）
→ 用户确认实际计划、输入、参数和资源
→ Analysis Contract 冻结
→ Adapter.materialize
→ Execution Gateway
→ 私有 HPC 中的固定工作流阶段
→ 输出验证与 QC 检查点
→ 产物登记与报告
```

LLM 只提出 capability ID、artifact ID 和 Schema 约束的参数。后端处理文件、SSH、命令和调度；LLM 输出不得指定任意脚本、入口或路径。新增 wrapper 必须固定入口、参数白名单、容器及输出契约。

保留主能力 ID `workflow.bulk_rna.grch38_pe_expression_fusion`。开发候选版本与批准 release 区分；不能在未验证时自称 `APPROVED_FOR_RESEARCH`。下游 DE/富集能力使用独立稳定 ID 并在计划中一次性登记。

## 5. bulk 分阶段流程

### Stage 0：输入、预检和计划

- 支持本地配对 FASTQ 以及用户授权的 HPC 只读根目录内的配对 FASTQ；远程输入不强制下载回本机。
- 完整检查 gzip/FASTQ 结构、序列与质量长度、R1/R2 read ID 与数量；检查重复样本、遗漏文件、输入 SHA-256 和存储权限。
- 样本表至少包含 `sample_id`、`subject_id`、R1/R2 关联、`condition`、`batch`、library strandedness；单样本未涉及分组时允许 condition 为空。缺失批次状态需显式登记，不能假装已检查批次。
- 区分样本、受试者和测序 lane；技术重复不算生物学重复。本版默认一个样本对应一对 FASTQ，多 lane 输入若未建立已验证的合并契约则拒绝并解释准备方式。
- 只接受人类 GRCh38 的首期正式 profile，检查 FASTA/GTF、STAR/RSEM 索引、Arriba 资源的一致性与摘要。不能仅凭文件名判断一致。
- 展示阶段、CPU/内存/时限、输出目录、上传量、参考版本、预计执行影响和模型外发策略；预估值明确标为预估。
- 输入不合格则停止相关路径；用户确认后冻结执行计划，再上传和执行获准阶段。

### Stage 1：真实 reads QC

运行冻结参数的 fastp，生成清洗后 reads、每样本 QC JSON/HTML，以及当前阶段的 MultiQC 汇总。验证输出后进入真实人工检查点。

展示 reads 保留、质量、接头等已实际计算指标，提供继续、修改重跑、排除样本、终止。QC 阈值和 WARN/FAIL 规则随 profile 冻结；AI 不得临时降低阈值以跑通。

QC 通过也保留可审计确认；损坏输入和输出契约失败不能以“仍然继续”绕过。排除样本生成新修订，并重新检查队列资格。

### Stage 2：比对、定量、融合

按既有 profile 依赖运行 STAR、featureCounts、RSEM 和 Arriba。上述描述是科学流程，不要求错误地把所有工具线性串联：必须核实 RSEM 的转录组比对输入与 Arriba 所需 STAR 输出/参数兼容。

产出 featureCounts 整数 counts、RSEM TPM、融合候选表、STAR 和定量 QC、版本/日志、汇总 MultiQC。禁止把 TPM 当 DESeq2 counts，禁止无说明地取整 RSEM expected counts 代替 featureCounts 原始计数。

核对样本列、基因 ID、注释版本、矩阵方向、重复基因策略。输出完成后进入比对后 QC 人工检查点。融合候选及过滤证据独立展示，不能由表达结果推断融合。

### Stage 3：条件开放的 DE 与富集

单样本在此结束统计主线，输出表达、融合与 QC 报告；DE 状态为 `NOT_EVALUABLE` 并解释原因，不生成假的差异基因表。

队列必须满足：

- 恰好两个 condition、独立生物学样本、无配对/纵向/重复受试者伪重复。
- 本草案采用每组至少 3 个独立生物学重复作为产品门槛；这是项目规则，不是对 DESeq2 理论最小样本数的声明。若现有 profile 不同，列明差异并由项目负责人确认后冻结。
- 固定公式 `~ condition`，显式记录 reference 和 treatment；正 log2FoldChange 表示 treatment 相对 reference 上调。
- counts 为合格整数计数，样本表与矩阵列严格一一对应；设计矩阵满秩、有剩余自由度。
- 完全混杂、配对或要求加入协变量的设计返回 `NOT_EVALUABLE`。可识别批次因素但当前模板不能合理处理时，说明限制并阻断需调整后的推断；不能自动做批次校正，不能声称忽略批次已消除影响。

执行固定 DESeq2 wrapper，保存完整结果（含非显著基因、NA 原因）、设计、contrast、过滤与多重检验规则。保存用于可视化的变换及参数，不能把画图矩阵送回正式 DE。

fgsea 使用预登记、许可允许且固定版本/哈希的 MSigDB 快照。冻结基因 ID 映射、去重、有限值筛选、排名方式、种子、gene-set size 与多重检验规则。默认以 DESeq2 带符号 Wald statistic 作为待冻结路线，不只拿显著 DEG 做预排序富集。保留 NES、P 值、调整值、leading edge 和有效覆盖率。

没有可用基因集资产时明确阻断富集并保留已完成 DE；不能伪造通路表，不能因此把整体完整验收标为通过。

## 6. 状态、恢复和修改

每个执行阶段分别经历：计划确认 → 提交 → `WAITING_HPC` → 终态与产物获取 → 输出验证 → QC/用户确认 → 下一阶段。

- LangGraph 使用磁盘持久化 checkpointer。进程重启后通过稳定 thread ID 恢复，不能依赖内存对象或浏览器状态。
- 长作业期间释放 HTTP 请求；任务中心轮询或接收事件。不能在 Web 请求里持续等待数小时。
- 提交前事务性登记幂等键；键包含规格修订、能力版本/manifest、输入哈希、规范化参数、执行目标及 stage 身份。
- 若提交已被调度器接受但返回连接断开，先用已记录提交标识核对远程作业。无法确定时保留“提交状态待核对”，不盲目再提交。
- 同一用户重复点击和重复恢复不得产生重复 HPC 作业。取消动作记录请求、目标 job 和确认后的调度器状态，不把“已发送取消”冒充“已取消”。
- 区分 `project_id/thread_id/spec_revision_id/run_attempt_id/scheduler_job_id/artifact_id`。文件路径不能代替这些标识。
- 失败保留诊断和 attempt；基础设施故障可有限重试，科学输入不适用不能自动改方法重试。

修改冻结内容必须创建 ChangeSet 和新修订：

| 修改 | 重新计算范围 |
|---|---|
| 更换 FASTQ 或 fastp 参数 | 受影响样本 QC 及其下游；队列矩阵、DE、富集和报告 |
| 参考/注释或 STAR 参数 | 比对、定量、融合及下游；未变 reads QC 可复用 |
| 排除样本或修改分组/比较方向 | 队列装配与设计检查、DE、富集和报告；合格单样本上游可复用 |
| MSigDB 快照或富集参数 | 富集及相关报告 |
| 仅报告排版 | 报告；科学结果不重新计算 |

历史修订保持可查看。旧结果相对于新修订标记不可消费/STALE，但不抹掉其在历史修订中的有效证据。后台仍在运行的旧 attempt 只能登记到旧修订，不能写入当前修订报告。

## 7. 输出契约与报告

每个 artifact 至少记录类型、Schema 版本、所属项目/规格/attempt/stage、输入依赖、内容 SHA-256、能力及参考版本、验证结论和存储定位。只有本项目、当前依赖有效的 `VALID + CONSUMABLE` 产物可进入下游。

| 路线 | 最低交付产物 |
|---|---|
| 全部 bulk | 输入和样本 manifest、FASTQ/比对 QC JSON、counts、TPM、fusion TSV、软件/参考与输出 manifest |
| 合格两组队列 | 样本表、design/contrast、完整 DE 表、统计参数与摘要、fgsea 全表/leading edge/映射审计 |
| 可视化 | QC 汇总；队列 PCA/样本关系、火山图、已说明筛选和尺度的热图、富集图；条件不满足则解释不生成原因 |
| 报告与归档 | 本地 HTML、PDF、TSV/JSON、方法与日志索引、可归档运行说明 |

零融合允许有效的表头和零行结果，但必须有运行成功及验证证据；不能把缺失文件当“未检出”。NA/无显著结果是允许的科学输出，应保留原因，不能改成 0 或伪造显著性。

输出先写 attempt 临时目录，通过 Schema/哈希/语义验证后原子发布；不合格结果进入隔离区并返回 `FAIL_OUTPUT_CONTRACT`。成功退出码、存在一个完成标志或空目录均不足以通过。

报告包含研究问题、样本和版本、QC 决策、表达与融合、条件性 DE/富集、限制、方法与产物链接。每个数值由已验证结果读取，LLM 只解释已提供证据。未运行的模型/WES/scRNA 不生成结果章节；不能把研究关联写成机制证明或治疗建议。

## 8. 网页与数据边界

页面采用 DeepScience 风格的精简科研工作台，详细设计见 `docs/superpowers/specs/2026-09-07-bulk-rna-workbench-ui-design.md`。至少包含项目/对话列表、流程及结果区域、对话与决策区域、任务状态，以及服务器/参考设置。检查点明确回答“发生了什么、需要决定什么、每个选择影响哪些结果”。刷新或重新打开浏览器不丢任务。

数据关系必须明确分层：`Project → Thread → Message` 保存对话，`Project → SpecRevision → RunAttempt → Artifact` 保存分析。一个项目允许多个对话；新对话默认能读取当前项目的有效产物和任务状态，但不自动读取其他对话的消息。对话的创建、重命名、归档或删除不得删除项目输入、运行或产物。多个对话请求同一冻结分析时必须经幂等检查，不能重复提交 HPC 作业。

只绑定 loopback；本地资源不依赖 CDN。实现随机会话凭据、Host/Origin 验证、CSRF 和 CSP。用户提供的路径、日志、样本名及聊天文本按不可信数据处理；不得成为可执行指令或未经转义的 HTML。

SSH 使用用户身份并验证 known_hosts；凭据不写入项目、日志或浏览器 localStorage。文件 ID 在后端解析，授权输入只读，所有写入限定当前项目/attempt，拒绝路径穿越与符号链接越界。

模型模式必须在用户输入研究内容前选定。公共模型外发只包含展示并获准的最小摘要，不默认包含 FASTQ、完整矩阵、逐样本敏感内容、真实路径、身份或凭据。模型不可用时，表单流程和既有任务恢复继续工作。

上述是产品运行时行为；不要求开发 AI 在每次可逆本地编辑前重新请示。

## 9. 开发里程碑

按依赖顺序推进；每阶段将具体文件、接口、测试及命令写入短实施计划，完成后更新证据，不提前宣称整个 Agent 完成。

| 阶段 | 工作与修改重点 | 验收门 |
|---|---|---|
| M0 现状审查与基线冻结 | 模块差距、现有测试；登记工具/容器/参考/参数/Schema/比较规则 | 有可核对差距表；锁定参考实现的输入、版本与实测容差，资源不足明确阻塞点 |
| M1 单样本 QC 闭环 | 输入、计划、合同、阶段化 fastp、真实 QC interrupt、持久化 | QC 产生前不能确认；恢复后能继续；修改后生成新修订 |
| M2 完整 bulk 上游 | STAR/定量/融合阶段、输出校验、QC Viewer | 实际产物齐全且可追溯；排队期间不误验收；零融合与文件缺失区分 |
| M3 队列统计 | 两组 Gate、DESeq2、fgsea wrapper、固定资产与图表 | 合格队列可完成；不适用设计拒绝；比较方向、基因/样本映射正确 |
| M4 修改与恢复 | ChangeSet、依赖传播、幂等提交、取消/失败恢复 | 故障注入无重复作业、无新旧结果混用、无跨项目产物消费 |
| M5 产品交付 | 统一网页、对话与表单同路、报告和安装说明 | 新用户按文档可启动；无 LLM 可跑主线；真实站点验证与模拟验证分开 |

安全和测试随各阶段落实，不能全部拖到 M5。M0 的小型参考运行可独立于产品进行，但仍需获准使用站点资源。

最终交付：代码、依赖锁与容器构建资料、版本化能力/参考清单、示例配置及无敏感测试数据、测试报告、公开基准运行记录、安装与站点预检文档、用户手册、限制清单和演示步骤。

## 10. 验收证据要求

至少覆盖以下独立行为：

1. 输入拒绝：截断 gzip、配对数量/ID 不符、重复样本、参考不一致、越界路径。
2. 真实检查点：未执行 QC 不得批准结果；批准必须绑定本次 QC artifact 和对应修订。
3. 持久化：在等待用户、排队、运行和已完成未下载四种状态重启，均恢复到正确阶段。
4. 幂等：提交响应丢失、重复点击、重复回调和并发恢复不产生重复任务。
5. 统计：单样本、技术重复冒充生物重复、配对设计、完全混杂、counts/TPM 混用和列错位均不能产生正式 DE 结论。
6. 输出：缺失/损坏/哈希不符/来源错误的文件不能被下游消费；零融合、NA 和无显著结果可正确展示。
7. 修订：改分组不重跑 FASTQ；改参考重跑受影响比对及下游；旧后台任务不能覆盖新结果。
8. 安全：跨项目读取、未授权 Origin、CSRF、恶意文件名/日志、提示注入和数据出口测试。
9. 模型降级：断开 LLM 后，表单配置、已批准执行、恢复和确定性报告仍可用。

测试分三层记录：本地单元/契约测试、调度器模拟与故障注入、真实 HPC 端到端。前两层不能替代第三层。

真实验证先使用仓库登记的 nf-core GSE110004 微型测试规格验证传输/调度基础，再使用 HBR/UHR ERCC 3×3 规格验证人源队列流程。前者是酵母工程测试，不得挂在人类 GRCh38 正式能力下冒充 bulk 黄金路线通过；后者的参考范围和输入版本也须明确核对，与完整 GRCh38 产品验收分别登记。

若这些已有数据规格不能覆盖正式 GRCh38 表达/融合全链，则补充并冻结适配的人类 paired-end 验证数据及参考资产；至少为融合解析建立阳性 golden fixture，并区分 fixture 校验与真实融合检测性能评价。数据来源、许可、资产 SHA-256 和预期结果必须可追溯，不能凭空填写 accession 或摘要。

先独立运行锁定参考实现，再比较 Agent 同输入、同参数执行的结果。检查样本身份、基因映射、counts/TPM、融合集合、contrast、DE/富集及数值容差；容差和性能门槛来自基线校准并在评价前冻结，不能看到结果后修改。

只承诺实际使用的一个调度器/站点的真实验收；其他适配器保留回归测试并准确说明验证范围。

## 12. 开工时如何处理未知项

先从已有配置和文档读取非敏感站点信息，不打印凭据。只有缺失时询问目标调度器、SSH 站点、授权输入/输出目录、资源上限及参考/镜像位置；凭据由用户通过安全配置入口提供。

本版草案对实施顺序、UI 复用、排除模型和每组三重复作了明确选择。项目负责人若调整这些条件，更新本文版本和相应合同/验收规则。原始多组学设计规范继续保留，不为本次缩小范围而改写成“多组学已完成”。
