# SYSU RNA-seq Agent 阶段二试验记录

## 一、阶段说明

本阶段主要围绕“把现有 RNA-seq 执行底座继续做成更像实验室同学可直接使用的对话式 agent”展开，重点不再是概念整理，而是实际功能落实，包括报告输出、共享动作层、项目会话式聊天入口、中文触发词和结果解释入口。

## 二、本阶段已完成内容

### 1. Markdown 报告能力落地

已将分析报告能力实际落实到项目中，完成了报告模块开发，可基于项目配置、日志、命令记录和结果目录生成标准化 Markdown 报告。

已实现的报告内容包括：

- 项目基本信息
- 输入样本信息
- 参考和运行设置
- 启用的 pipeline 步骤
- 运行时间线
- 命令摘要
- 结果文件清单
- 结果阅读说明
- 风险与缺口提示

对应代码位置：

- [src/rnaseq_agent/report.py](src/rnaseq_agent/report.py)

并已成功生成示例报告：

- [runs/report_demo.md](runs/report_demo.md)

### 2. 新增共享动作层，统一 CLI / chat 后端能力

为避免不同入口重复写逻辑，已新增轻量服务层 `actions.py`，把项目配置读取、保存、校验、运行、状态刷新、报告生成、摘要展示等能力集中到统一动作层中。

该层已经实现的主要能力包括：

- 读取并标准化项目配置
- 保存项目配置并生成运行估算
- 校验项目输入
- 启动运行
- 刷新状态
- 生成报告
- 输出验证摘要与状态摘要
- 读取缓存状态

对应代码位置：

- [src/rnaseq_agent/actions.py](src/rnaseq_agent/actions.py)

这一层的完成，使后续 GUI / chat / CLI 复用同一套后端逻辑成为可能。

### 3. chat 入口由一次性问答改造成项目会话模式

已将 `chat.py` 从原来“一次性收集配置后退出”的形式，改造成“项目会话式”交互模式。

当前 chat 已支持：

- 新建项目
- 打开已有项目
- 校验配置
- 运行项目
- 后台提交运行
- 查看状态
- 生成报告
- 查看项目摘要
- 查看当前项目路径
- 显示帮助
- 退出会话

这意味着系统已经从“单轮问卷式工具”迈向“可持续操作当前项目的对话式入口”。

对应代码位置：

- [src/rnaseq_agent/chat.py](src/rnaseq_agent/chat.py)

### 4. CLI 与新动作层完成对齐

已对 `cli.py` 做重用式调整，使其改为调用新的动作层，而不是各自分散处理逻辑。

本阶段还补充了一个重要能力：

- `status --cached`

该能力允许在远程服务器尚不可达、示例主机名为占位符时，仍可直接查看当前 `project.json` 中缓存的状态信息，便于本地演示和项目调试。

对应代码位置：

- [src/rnaseq_agent/cli.py](src/rnaseq_agent/cli.py)

### 5. 增加中文自然触发词支持

为了让 chat 更接近实验室同学真实使用方式，已为会话入口增加一批中文触发词，而不再只支持严格英文命令。

目前已支持的典型中文表达包括：

- 新建项目
- 打开项目
- 校验 / 检查配置
- 运行 / 开始运行
- 看看状态 / 当前状态
- 生成报告 / 写报告
- 项目摘要
- 项目路径
- 帮助
- 退出

这一步的意义在于：

系统开始从“命令式 chat”向“自然表达式 chat”过渡，更适合实验室日常使用场景。

### 6. 增加结果解释入口

本阶段还为 chat 增加了 `explain / 解释结果` 入口，用于给出模板化的结果解读建议。

当前解释入口已能围绕以下内容给出说明：

- 先看当前 status 所处状态
- 未完成项目应先看提交和状态问题
- fastp 结果应关注质控与剪切
- star 结果应关注比对日志
- featureCounts 应关注 gene count 矩阵
- RSEM 应关注表达定量结果
- Arriba 融合结果仍需人工复核
- 更正式汇报时应结合 report 和下载目录统一讲解

这一能力虽然还是第一版模板化解释，但已经让项目更接近真正可用的实验室 agent，而不是单纯流程包装器。

## 三、本阶段完成的验证工作

1. 已验证示例报告可成功生成。
2. 已验证本地校验会正确提示缺失 FASTQ 文件。
3. 已验证 `status --cached` 能在占位服务器配置下正常返回缓存状态。
4. 已验证 chat 中文触发词能够路由到对应功能。
5. 已验证 `解释结果` 入口可以正常调用并输出模板化结果说明。

## 四、本阶段形成的关键判断

1. `run_agent.py` 应保持稳定，继续作为确定性执行核心。
2. chat / CLI / GUI 应尽量共享统一动作层，而不是各写一套。
3. 第一阶段的“对话式 agent”不等于自由聊天，而是围绕当前项目进行会话操作。
4. 对实验室用户来说，状态查看、报告输出和结果解释与执行能力同样重要。
5. 先把 RNA-seq 做成可解释、可展示、可复用的闭环，比过早扩展多流程更重要。

## 五、本阶段仍存在的问题

1. 当前 chat 仍然是规则路由型，还不是自由理解型智能对话。
2. 结果解释仍然是模板化第一版，尚不能替代人工专业判断。
3. 真实样本、真实服务器、真实运行闭环还没有完全跑通。
4. GUI 和 wizard 还没有完全复用新的动作层。
5. 外部检索失败问题仍需后续继续排查。

## 六、下一阶段计划

下一步建议继续围绕以下方向推进：

- 进一步增强 chat 的自然语言理解能力
- 继续补强结果解释和实验室可读报告
- 将 GUI 和 wizard 逐步对齐到统一动作层
- 用真实数据和真实服务器完成一次完整演示
- 在 RNA-seq 基础稳定后，再考虑 ChIP-seq / WES 扩展
